# Codex — efficient Astro site conversion

This repo is a reusable **source/layout starter**, not a content-install system. Existing MW4 copy, prices, images and partner links are **scaffold values**, not facts for a new website. Work only in this clone; the owner runs six external prompts in order. No prompt files are stored here.

## Efficient rules (all parts)
- Read this file once; consult `docs/CODEX_MAP.md` only when locating source owners, then inspect just the relevant files. Use narrow searches (`rg -n`) to locate fields; don't dump the entire repository or re-research finished decisions. Prefer reusing existing components, CSS, routes, UI interactions, SEO/i18n utilities and `.agents/skills/` as needed. Avoid library/framework upgrades, new components, or redesign unless a real gap requires it.
- Modify native `src/` and `public/`, **never `dist/`**. Use one `npm run dev -- --host 127.0.0.1` process; inspect the actual printed URL. Astro dev updates source immediately. If localhost seems unchanged, check `pwd`, dev port, source and browser cache; git staging does not affect rendering.
- Ask **one grouped question** when a material business/product detail cannot be safely resolved (checkout destination, option availability, compatibility, product inclusion, destination, rights, ownership). Continue unblocked work. Do not ask about routine editorial choices or repeat answered questions.
- The user-facing review system is intentionally absent. Do not recreate review pages, product review components, star ratings, aggregate ratings, importer scripts or a reviews step. Forum content is a separate owner-supplied workflow.
- Original content must fit existing slots: punchy hero and cards, substantial product/feature/requirements/FAQ/guide copy. Avoid thin or spun text. Rewrite all 3 supporting utility pages' body copy per site while preserving verified features, product names/headings, and protected artwork. Maintain meaningful EN/ES/DE/FR versions; do not fabricate claims or user experiences.
- **Visual layout is a fixed acceptance criterion:** read `docs/VISUAL_FIDELITY.md` once at the beginning of Part 1. Keep section order, max-width containers, grid/bento spans, breakpoints, spacing rhythm, card alignment, typography, carousel/gallery aspect ratios, header/footer, and checkout controls matching the scaffold. Rewrite text within the existing slots, keeping cards compact and detail sections substantial. Do not alter UI/CSS or rearrange sections just for distinct SEO copy. Capture `visual:baseline` before conversion when Chrome is available; use `visual:check` in Part 5. Treat actual mobile overflow, text clipping, displaced buttons and unexpected alignment differences as bugs.
- **No onsite price cards, totals, plan selector, price comparison or plan-parameter generation.** Preserve the product card, checkout panel, mobile bar and two-column layout, with one localized **View Purchase Options** action (preserve the existing EN/ES/DE/FR strings exactly) that uses the existing `/go/{cheats,hwid-spoofer,skin-changer,cloud-dma}/` routes in `src/config/checkout-redirects.mjs`. Prices and available terms are presented at destination checkout. Remove any obsolete old-template price/plan promises from page content and metadata when converting. Never misstate required companion purchases, subscriptions, product fulfillment or affiliate relationships. Qualify sponsored affiliate links and provide appropriate transparency; do not fabricate customer feedback.
- Do not add full-site test loops in every part. Parts 1–4: targeted checks and real dev spot checks; Part 5: single comprehensive fresh build, tests, validation and browser/SEO audit. Rerun affected checks after fixes. Report what actually ran; no guaranteed rankings or performance claims.
- The six external stages are: (1) conversion, (2) supplied forum, (3) media, (4) internal links, (5) final audit, (6) GitHub push. Do not create review pages/import stages. No Git stage/commit/push/deploy until Part 6. Do not restore approval/content pack workflows. Handoff notes at `.content/handoff.md` are optional and ignored by Git.
